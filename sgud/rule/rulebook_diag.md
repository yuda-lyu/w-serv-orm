# 規則帳本: 診斷輸出(console)

本檔收 R-DIAG-01. 通則與其他規則見 `rulebook.md` 之分檔索引.

## R-DIAG-01 診斷輸出不得含資料值: 預設只輸出標籤與不含個資之摘要,完整細節由 `opt.logDetail` 或 `opt.funLog` 取得

- 狀態: 已套(2026-10-28 orm-run01,未提交、未發布).來源: w-web-perm 主責 agent 之建議書(Gitea #12,根目錄 `建議w-serv-orm修正.md`,主控發布前移除),主控判斷屬實、屬本套件範疇.
- 起因: 下游(w-web-perm、w-web-sso 等)主鍵為使用者 id(含 email),其政策是 log 與 API 回應皆不含 id、email、name;本套件原以 `console.log` 輸出失敗列 `{k, id, err}`(`save fail`、`del fail`)與 ORM 拋出之錯誤原文(`insert catch`、`save catch`、`del catch` 等),下游無從遮罩,而行程標準輸出常被 pm2、容器 log 收集.
- 單一擁有者: `src/getDiag.mjs`(`getOptLog`、`getOptLogLoose`、`getDiag`、`getBriefErr`、`getBriefFails`、`getBriefResult`、`getBriefType`、`getBriefCount`).**`src/` 內除 `getDiag.mjs` 之 `diag` 本體(4 處 `console.log`)外,任何檔不得直接輸出**(S01 以識別字 `console` 計數鎖定,S02 鎖定 `process.stdout/stderr`、`writeSync`、`emitWarning`、`debuglog`).每個 `getMapOrm(...)` 呼叫(即每個 WServOrm 實例)各自持有一個 `diag`.
- 規則:
  1. **預設安全**: 所有診斷輸出預設只輸出標籤(含表名與操作,沿用舊版標籤)與摘要;摘要只含: 筆數與前 10 筆之位置(`{ n, ks }`)、聚合結果之 `ok:0`(`{ ok: 0 }`)、錯誤類別與代碼(`{ errType, errCode? }`)、被拒條件之固定拒收句(`{ reason }`)、呼叫端傳入之無效參數的型別(`{ type }`)、設定檔之已知鍵與未知鍵個數(`{ keys, nOther }`)、資料表名清單(`{ n, tables }`)、測試資料筆數(`{ n }`);**不含**主鍵值、資料值、錯誤訊息文字、條件值、呼叫端傳入之參數值.
  2. **摘要之錯誤類別與代碼**(外審 terra F04 後收窄): `errType` 只取原生 Error 之**建構子名稱**(程式識別字,非資料;驅動程式常以原型存取器宣告 `name`,且 `name` 可被改寫,故不取),須合 `^[A-Za-z][A-Za-z0-9_]{0,39}$`,否則 `Error`;`errCode` 只放行自有資料屬性 `code` 之機器代碼: 絕對值至 99999 之整數,或合 `^(E[A-Z0-9]{2,15}|ERR_[A-Z0-9_]{1,40}|[0-9A-Z]{5})$` 之字串(ENOENT 類、`ERR_` 開頭、SQLSTATE 5 碼且前 2 碼為已知類別〔外審 R2-01 加嚴〕);字串 reject 為 `{ errType: 'string' }`;Proxy 為 `{ errType: 'Proxy' }`;全程只用 `util.types` 與屬性描述子,不執行 getter、不觸發 Proxy 陷阱(同 R-OBJ-01 規則 6 ⑤).已知限制: 樣式不能證明 `code` 不是資料(慣例上 `code` 為機器代碼,ORM 不會把主鍵放進去),未改為固定映射表以免失去 Mongo 11000 等診斷資訊.標籤中的 `mode` 只放行固定清單(`select insert save del delAll mix`)、表名只放行 `woItems` 之自有鍵(外審 terra F06).
  3. **可控**: `WServOrm(ds, WOrm, url, db, opt)` 之 `opt.logDetail`(布林,預設 false;true 時 console 還原為舊版完整細節,逐站相同;舊版為 `console.log(err)` 者以 `bare` 還原為單一引數)與 `opt.funLog(label, safe, detail)`(函數;給予時診斷輸出只交給它,本套件不寫 console,含進度、無效參數、設定檔錯誤;`detail` 為完整細節含主鍵與錯誤原文;優先於 `logDetail`).`undefined` 與 `null` 視為未給(同 `checkOptRemoved`、`procOrm` 之 `opt`;外審 F13 要求 null 拋錯,**不採納**,理由: 任務條件允許與其他選項一致);**型別錯誤於建構時拋 `Error`**(`invalid opt.logDetail, need a boolean`、`invalid opt.funLog, need a function`),早於建立各資料表 ORM;選項只讀取一次,以固定快照交各路徑(F12).工具路徑(`getDb.backup/recover`、`genTestData`、`getSettings`)之 `opt` 同名選項**型別錯誤、讀取拋錯者忽略並用預設**,同其 `bLog` 之慣例.
  4. **回傳契約不變且診斷輸出不得影響結果**: `procOrm` 之 resolve 與 reject 內容與時機不因診斷選項改變(逐筆失敗之 reject 訊息照舊列主鍵,R-MSG-01);`recover`、`genTestData` 拋出之 `Error` 訊息(含 ORM 回傳原文,R-DB-01 規則 3、R-ORM-RESULT-01)為回傳契約,不受本規則影響.與其後流程共用的細節(失敗清單、拋給呼叫端之 `Error`、傳給模型產生器之 schema 等)交給 `funLog` 的是**深層拷貝**(`cpDetail`,**只用內建操作,不執行使用端程式〔getter、實例方法、建構子〕**): 複製純物件與類別實例〔保留原型參照,複製自有屬性,存取器不執行而以 `[Getter/Setter]` 保留其鍵〕、陣列〔含空洞、長度與自有非索引鍵〕、原生 Error〔`stack` 為 V8 同 realm 共用的內建存取器 `STACK_GETTER` 時讀取後以資料屬性放入,取得描述子包 try 且回傳須為字串,其餘存取器不執行,不以函數原始碼字樣判斷信任〕、Date〔`Date.prototype.getTime.call`〕、Map、Set〔`Map.prototype.entries.call`〕及其自有屬性;以標記字串代替: 函數 `[Function]`、Proxy `[Proxy]`、RegExp `[RegExp]`、二進位資料〔Buffer、TypedArray、DataView、ArrayBuffer: `[Binary n bytes]`,以內建 byteLength getter 取得,不經 `structuredClone`,故無共享記憶體、無 Buffer 變 Uint8Array、無小視圖牽動巨大底層緩衝區之問題〕、SharedArrayBuffer、Promise 等無法複製的內建物件 `[Object]`、深度超過 8 或處理的節點與鍵合計超過 5000 者 `[Truncated]`,**不交出原參照**;稀疏巨陣列與寬陣列只處理既有鍵、受預算限制,存取器鍵亦計入預算),摘要中之訊息陣列為 `[...msgs]` 拷貝,使用端原地遮罩不改變 reject 與工具路徑拋出之原錯誤(外審 F08、R2-03、R2-04、R2-15);`recover` 之 Error 訊息先於診斷輸出組出,組訊息拋錯(如結果含循環)者仍先輸出診斷再拋出同一錯誤(F08、R2-08);`adjustData` catch 內 `e.toString()` 維持**立即求值**(同舊版,拋出 null 者仍為 `failed to process input`,F10);`funLog` 同步拋錯、回傳 rejected promise 或 thenable 皆被吞下(原生 promise 以 `Promise.prototype.then.call` 附處理,不讀可被覆寫之 `then`;其他 thenable 只讀一次 `then`,F09);細節取得拋錯以 `(unprintable)` 代替.刻意保留的唯一差異: 診斷輸出自身拋錯(如 console 格式化使用端物件時拋錯)時,舊版部分未經 `logSafe` 之站點會使 procOrm 轉為 `failed to process input`,新版一律吞下.
  5. **新增輸出站點須先歸類**: `test/unit-diaglog.test.mjs` S01(以識別字 `console` 計數,涵蓋別名與方括號記法)、S02(其他輸出途徑)、S03(`getMapOrm.mjs` 之每個 diag 標籤皆有路徑表案例涵蓋,`${mode}` 展開 insert/save、`${key}` 展開 add/diff)任一不一致即失敗.
- 已知限制與刻意取捨(外審兩輪後仍保留,待主控知悉):
  1. **`errCode` 為驅動程式設定之機器代碼,樣式白名單不能證明它不是資料**(外審 F04、R2-01 認為應改固定映射): 慣例上 ORM 不會把主鍵放進 `code`;若改固定映射會失去 Mongo 11000 等診斷資訊.若需絕對保證,改為只輸出 `errType`.
  2. **表名視為非個資**(外審 R2-02 不採納): 任務條件明列可輸出「表名」;資料表名由部署者於 schema 定義.標籤含表名、`backup...`/`recover...` 進度與 `tabs` 之 `tables` 清單皆含表名.
  3. **惡意 promise 不在保證內**(R2-05): `funLog` 回傳之原生 promise 其 `constructor`/`Symbol.species` 拋錯者,內建 `then` 於附加處理前拋錯,rejection 無處理者;一般 rejected promise、async 函數、thenable(含其 `then` 回傳 rejected promise)已處理.
  4. **診斷輸出自身拋錯時不再改變結果**(R2-09): 舊版未經 `logSafe` 之站點遇 console 格式化拋錯會使 procOrm 轉為 `failed to process input`,新版一律吞下;視為修正.另 `recover` 之 Error 訊息與診斷輸出之先後次序對調(先訊息後診斷,為 F08 所需),僅在使用者之 `inspect.custom` 於格式化時改動結果物件這種病態情形下與舊版不同.
  5. **被拒 find 之細節為有上限之純資料快照**(R2-13,舊版即如此): 字串 200 字、深度 8、每層 50 項、200 個節點,Proxy 與存取器以固定字樣代替,非原值.
  6. **實例上之 `backup`/`recover` 為各實例之包裝**(F16、R2-14): AsyncFunction 型態與 `length`(1、3)不變,函數身分跨實例不同,多一個 async 包裝之微任務.
  7. **細節拷貝之標記與截斷**: `cpDetail` 超過深度 8 或節點與鍵合計 5000 者以 `[Truncated]` 代替,函數、Proxy、RegExp、二進位資料、Promise 等以標記代替(`logDetail`/`funLog` 收到的細節因而不是這些值的原值,外審 R4-05 的 Buffer 型別轉換因而改為明確標記);類別實例以原型加自有屬性複製(不執行建構子,私有欄位不存在),**與其複本共用原型**(原型上的可變狀態仍共用,外審 R3-02 指出,視為合理: 原型屬程式碼而非資料);`WeakMap`、`WeakSet`、包裝物件、產生器、迭代器等以 `[Object]` 代替.
  8. **站點護欄為詞法檢查而非證明**(外審 R3-07、R4 之 R3-07 殘留): S01、S02、S04 以逐行詞法掃描(字串感知的註解剝除、依檔白名單、站點數)鎖定; 蓄意以多行模板字串內的插值、區塊遮蔽變數名稱等方式規避者,不在其保證內,仍需人工審查.
  9. **逐筆結果摘要之 `skipped`**: 元素為 Proxy、原型鏈有 Proxy、`ok` 或索引為存取器、空洞且陣列原型非標準者不執行、不計入並加 `skipped`;掃描上限 100000 筆,超過者計入 `skipped`.
